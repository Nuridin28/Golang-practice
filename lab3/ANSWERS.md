# Lab 3 — ответы на вопросы

## Part 1: Structs

### `%v`, `%+v`, `%#v`
```
{ 0 0 []}                                                          // %v  s1: только значения
{Name:Aruzhan ID:1 GPA:3.8 Courses:[]}                             // %+v s2: + имена полей
main.Student{Name:"Dias", ID:2, GPA:3.2, Courses:[]string{"Go", "Databases"}} // %#v s3: синтаксис Go
true                                                               // nil-слайс у нулевой структуры
```
- `%v` — только значения полей.
- `%+v` — значения с именами полей.
- `%#v` — Go-синтаксис: имя типа, строки в кавычках, типы слайсов.

### Team
```
Gophers [1 2 3] [Nurlan Bota]
Rustaceans [100 2 3] [Nurlan Bota]
```
`t2 := t1` копирует все поля. `Name` (строка) и `Scores` (массив — это значение) скопированы полностью, поэтому их изменения не видны в `t1`. `Members` — слайс: скопировался только заголовок (ptr, len, cap), а базовый массив общий. Поэтому `Members[0]` изменился в обеих структурах.

### Сравнение структур
```go
a == b   // true  — сравниваются поля, они равны
c == d   // false — сравниваются адреса, это два разных объекта
*c == *d // true  — сравниваются сами структуры
```
`t1 == t2` для Team: `invalid operation: t1 == t2 (struct containing []string cannot be compared)`.

## Part 2: Embedding

### Animal / Dog

`d.Describe()` — это на самом деле `d.Animal.Describe()`. Внутри `Describe` получатель имеет тип `Animal`, поэтому `a.Sound()` — это всегда `Animal.Sound`. В Go нет виртуальных методов: внутренний тип ничего не знает о внешнем `Dog`. Это и есть отличие встраивания от наследования.

### Task 4: какой ресивер у Balance()?
Указатель, как и у остальных. `Deposit`/`Withdraw` обязаны быть pointer receiver (меняют баланс). По правилу согласованности из Go FAQ, если хоть один метод на указателе, то и все на указателе. Плюс: если позже добавить `sync.Mutex` для потокобезопасности, value receiver копировал бы мьютекс (`go vet`: *passes lock by value*).

### Task 5: бенчмарк (Apple M4, go1.27.1)
```
BenchmarkFirstValue-10      8390416        128.5  ns/op   0 B/op   0 allocs/op
BenchmarkFirstPointer-10    1000000000       0.75 ns/op   0 B/op   0 allocs/op
BenchmarkPointValue-10      1000000000       0.72 ns/op   0 B/op   0 allocs/op
BenchmarkPointPointer-10    1000000000       0.71 ns/op   0 B/op   0 allocs/op
```
- **Почему B/op = 0?** `-benchmem` считает только аллокации в **куче**. Копия `Report` (8 KB) делается на **стеке** вызывающей функции как аргумент вызова. Это не аллокация, сборщик мусора её не видит.
- **Где видна цена?** В колонке **ns/op**: ~128 ns против ~0.75 ns, то есть примерно в 170 раз медленнее из-за копирования 8 KB на каждый вызов.
- **Point:** 16 байт копируются так же дёшево, как 8-байтовый указатель, поэтому разницы нет. Для маленьких типов value receiver ничего не стоит.
- **`//go:noinline`** запрещает компилятору встраивать функцию в место вызова. Без этого компилятор встроил бы `FirstValue`, увидел бы, что нужен только `r.Values[0]`, и выкинул бы копирование. Тогда бенчмарк измерял бы не то, что мы хотим.

## Part 5: Method sets

### Почему `Dog{}` нельзя положить в `Speaker`?
Метод `Speak` объявлен на `*Dog`, поэтому он есть только в method set `*Dog`. `d.Speak()` на переменной работает, потому что переменная адресуема и Go подставляет `&d`. А значение внутри интерфейса — это копия, которая **не адресуема**: взять её адрес нельзя. Даже если бы было можно, метод менял бы скрытую копию, а не исходный `Dog`. Поэтому компилятор запрещает это заранее.

### A–D
`Base`: `Hello` на `Base`, `Speak` на `*Base`.

| Строка | Компилируется? | Почему |
|---|---|---|
| A `&ByValue{}` | ✅ | method set `*S` при встраивании `T` = методы `T` и `*T` → есть `Speak` |
| B `ByValue{}` | ❌ | method set `S` при встраивании `T` = только методы `T` → `Speak` нет |
| C `ByPointer{...}` | ✅ | встроен `*Base` → у `S` есть методы `T` и `*T` |
| D `&ByPointer{...}` | ✅ | то же самое для `*S` |

### Book
```
{The Go Programming Language Donovan & Kernighan}
The Go Programming Language by Donovan & Kernighan
```
`String()` объявлен на `*Book`, поэтому `fmt.Stringer` реализует только `*Book`. `fmt.Println(b)` получает значение `Book`, у которого нет `String()`, и печатает поля. `fmt.Println(&b)` получает `*Book` и вызывает `String()`.

### Task 6: `Circle{Radius: 1}` в `[]Shape`
```
cannot use Circle{…} (value of struct type Circle) as Shape value in array or slice literal:
Circle does not implement Shape (method Area has pointer receiver)
```
У `Circle` пустой method set: `Area` и `Perimeter` есть только у `*Circle`. Нужно класть `&Circle{...}`.

### ⭐ Бонус: method value
```
12 40
```
`f := r.Area` вычисляет получатель **в момент создания** method value. Так как ресивер value, `r` копируется сразу (Width=3). Последующее `r.Width = 10` на `f` уже не влияет. Если бы `Area` была на `*Rectangle`, сохранился бы `&r`, и `f()` вернул бы 40.

## Теоретические вопросы к защите

**Что такое struct и чем он отличается от класса?**
Struct — типизированный набор именованных полей, то есть просто данные. В отличие от класса в Java/C++, нет наследования, конструкторов, деструкторов, модификаторов `private`/`protected` (видимость по регистру первой буквы на уровне пакета) и виртуальных методов. Методы объявляются отдельно, для любого именованного типа пакета. Struct — это значение, а не ссылка.

**Что происходит при присваивании struct?**
Копируются все поля побайтно. Массивы копируются целиком. Слайсы, map, указатели, каналы копируют только «ссылку», так что базовые данные остаются общими.

**Что делает встраивание и почему это не наследование?**
Встраивание добавляет поле без имени (имя поля = имя типа) и продвигает его поля и методы во внешний тип. Это лишь сокращение записи: `e.Name` → `e.Person.Name`. Внешний тип не является внутренним (`Employee` нельзя передать туда, где ждут `Person`), нет полиморфизма: метод внутреннего типа всегда вызывает методы внутреннего типа (пример `Dog`/`Animal`).

**Value receiver vs pointer receiver?**
Value receiver получает копию, изменения не видны снаружи. Pointer receiver получает адрес и работает с оригиналом, без копирования. Ресивер — это просто первый параметр функции.

**Почему pointer-метод можно вызвать на переменной, но не на элементе map?**
Для вызова Go должен взять адрес `&x`. Переменная адресуема, а элемент map — нет: при росте map переносит элементы в памяти, и указатель стал бы недействительным.

**Method set `T` и `*T`?**
`T` — методы с ресивером `T`. `*T` — методы с ресивером `T` и `*T`.

**Почему `Dog{}` не реализует интерфейс, если `Speak` на указателе?**
`Speak` не входит в method set `Dog`. Значение в интерфейсе не адресуемо, поэтому Go не может автоматически подставить `&`.

**Когда выбирать value receiver?**
Тип маленький и ведёт себя как значение (`Point`, `Celsius`, `time.Time`). Метод только читает, а копия дешёвая. Тип — именованный слайс/map/базовый тип. Нужна неизменяемость: метод гарантированно не изменит оригинал. И только если ни одному методу типа не нужен указатель.
